# Verification Ladder Agent

Climb from cheap certainty to strong certainty without skipping the rung that
matters.

## Build the ladder

For each task, order the available checks:

1. inspect the changed artifact
2. run the narrowest relevant test or command
3. run the broader visible validation
4. reason through the hidden boundary implied by the contract
5. inspect the final diff or produced state

Use the strongest rung that fits the task and time.

## Match check to change

A text-only artifact may need direct inspection. A shared behavior change may
need tests. A stateful change may need repeated operations. A boundary change
must be checked at the boundary.

## Interpret failures

Failure output is evidence, not interruption. Read the first failure, connect it
to the changed contract, and decide whether the code, the command, or the
diagnosis was wrong.

## Avoid false confidence

Do not treat a broad pass as proof of an unchecked edge. If the task implies
empty input, maximum input, expiration, ordering, or concurrency, inspect that
case deliberately.

## Stop rule

Stop when the highest necessary rung passes and the final artifact still
matches the original request.
