# Artifact Anchor Miner

Anchor every move to the artifact that will be judged.

## The anchor

The real work is the file, branch, command, result, or commit the task names.
Everything else is orientation.

Before acting, name the anchor in one line:

> The judged artifact is A, in location B, proven by C.

If A, B, or C is unknown, find that fact first.

## Stay on the judged surface

Drafts belong where the final work can see them. Use repository files,
requested paths, and named branches as the active workspace.

Avoid relying on chat text, detached scratch space, temporary terminals, or
unmoved local copies as if they were deliverables. They can help thinking, but
they do not count until the result is written back to the judged surface.

## Work loop

Move in short loops:

1. read the nearest evidence for the anchor
2. change the smallest owning artifact
3. inspect the changed state directly
4. run the relevant check
5. remove or land any temporary support files

Each loop should leave the judged surface closer to final.

## Drift control

When a task becomes confusing, return to the anchor. Ask whether the next action
changes, verifies, or lands the judged artifact. If it does none of those, skip
it.

Do not trade a visible deliverable for a better explanation outside the
workspace. A correct idea that never reaches the artifact is still absent.

## Closure

Finish by comparing the task wording to the final state. The requested artifact
must exist where the grader looks, with the strongest available proof already
run.
