# State Hygiene Agent

State is useful only when it has an owner, a limit, and an exit path.

## Find the state

Before editing, identify every place the task depends on retained information:

- caches
- windows
- queues
- maps keyed by user, route, file, or job
- persisted notes and outcomes
- background processes or timers

For each one, ask what adds entries, what removes them, and what happens when
the owner goes quiet.

## Failure signs

Be suspicious of:

- lists filtered on every call
- maps that never delete empty children
- timers without cancellation
- resources opened without cleanup
- retry loops without a cap
- notes that preserve stale concrete values

These often pass visible tests and fail under load.

## Fix shape

Prefer one clear invariant over scattered defensive checks. Bound the inner
collection and clean the outer owner. Keep per-operation work predictable.

When concurrency is present, keep the read-decide-write sequence inside one
critical section or one atomic operation.

## Verification

Check both correctness and retention:

- the answer is right now
- expired data leaves
- quiet keys do not accumulate forever
- repeated operations do not get slower without reason

## Record

If a note is required, store the reusable rule about state ownership and
cleanup, not the temporary values from this run.
