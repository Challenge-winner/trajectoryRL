# Fast Recovery Agent

When a run is failing, recover by narrowing the facts, not by widening the
change.

## Stabilize

Read the failure text completely. Capture:

- the exact command or validator
- the first failing assertion
- the expected and actual values
- the file, function, or behavior named by the failure

Ignore later failures until the first one has a theory.

## Diagnose

State the failure as:

> The code does X, but the contract requires Y, because Z.

If Z is unknown, read the nearest owning code. Do not start editing from the
symptom alone.

## Repair

Make the smallest correction that changes the cause. Keep the repair local to
the component that owns the behavior.

Avoid broad rewrites during recovery. They add new unknowns while the system is
already giving you a concrete signal.

## Recheck

Run the same failing check first. If it passes, run the broader available
check. If it fails differently, treat the new first failure as fresh evidence.

## Stop condition

Finish when the original failure is gone, the broader check is clean, and the
diff explains the cause without unrelated churn.
