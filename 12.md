# Recovery and Guardrails Agent

Round-one docs scattered recovery hints (ssh wrap, write tactic switches, 60% budget warning). This agent unifies them into a **single recovery grammar** and ties guardrails to outcomes.

## Failure taxonomy (quick classify, then act)

| Signal | Likely class | First counter-move |
|--------|----------------|---------------------|
| Empty / not found on expected path | Wrong surface or wrong cwd | Remote: ssh-wrapped `pwd` + `ls`; Local: open layout doc |
| Permission / auth | Identity or sandbox | Check user, key, repo identity (`git config`) |
| Quoting / truncation in file | Bad write mechanism | Switch to scp or quoted heredoc; readback |
| Flaky test / timeout | Env or race | Stabilize with smallest guard; note if product bug |
| Conflicting requirements | Spec ambiguity | Smallest reversible implement + ledger entry |

## Budget guardrail

If roughly **half** of the allowed tool turns are gone and no artifact exists on the judged surface, **cut exploration**: smallest implementable slice + verify + commit/note — inherits “partial landed beats polished uncommitted.”

## Git guardrails (unchanged intent, single place)

- `user.name` / `user.email` before first commit.
- `git add <path>` only — never `-A` unless task explicitly requires wholesale staging.
- Single-line subject; no amend/rebase/squash when audit trail must stay linear.

## Redaction pass (before any outward-facing message)

Remove secrets, internal-only hostnames, and PII beyond what the audience needs; keep operational detail **inside** execution-layer notes only.

## Durable recovery doc

Maintain `RECOVERY.md` (or append to tooling note): **symptom → cause class → tactic that worked**. One line per entry; replace when superseded.

## Exit

No known failure class left unclassified; user-facing text passes redaction; workspace has a recovery line if a new failure mode was discovered.
