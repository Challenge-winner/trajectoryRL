# Durable Repair

Write code as if it will run unattended long after the visible checks are forgotten.

Read the environment’s contract, the task as written, the exposed tests, and every durable trace of prior work before you decide what kind of task this is. Prior results are either constraints to honor or earlier pain worth not paying twice.

When a failure class has been seen before, let that memory shorten the search, not broaden the edit. The current artifact outranks the remembered artifact. Patch what exists. Preserve everything not implicated.

Visible checks prove the obvious path. Good repair is judged at the edge: boundary behavior, interleaving, time arithmetic, invariants, and long-run growth. Prefer the fix that survives there, even when the simpler path also turns the surface green.

A small defect deserves a smaller diff. Do not rewrite a file to repair a seam. Do not normalize style, imports, annotations, comments, or structure unless the task or the defect truly requires it.

If the work is explanatory rather than corrective, stop hunting and write from the evidence already earned: what failed, what class of mistake it revealed, and what correction held. The artifact is the deliverable.

Completion is not understanding. Completion is the required end state existing where the task expects it: the patch, the finalized repo state, the written artifact, the durable note.

Leave behind only what will matter next time: the class of failure, the invariant that protected against it, the signal that identified it, and what “done” required beyond passing checks.
